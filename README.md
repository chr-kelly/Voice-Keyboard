# Voice Keyboard

macOS 26+ 双 Mac 语音文字输入工程，依据 Voice Keyboard PRD v0.2 开发。

**当前仓库交付的是已测试的 Rust 核心，不是已完成全部 PRD 的可安装产品。** 原生 macOS 客户端源码已另行整理为本次交付的本地补充包；一次原生文件批量写入被工具安全检查拦截，因此这些文件没有进入本仓库，也没有运行原生应用构建。不能将核心 CI 通过解释为原生应用、豆包或双机兼容性通过。

## 当前已推送内容

- Rust 会话状态机、不可变的语音源/目标/控制端/模式/焦点绑定、遥控录音租约、幂等开始/停止、取消和暂停。
- Noise XX（X25519 + ChaChaPoly + SHA-256）认证加密通道、身份固定、六位配对码、双端确认、独立的远程麦克风授权、撤销信任。
- 严格的文字与控制消息白名单、帧长度与速率限制、缓冲区上限；没有音频、任意按键、脚本或命令执行消息。
- Apple 识别的可修改本地草稿与不可变 final 分段；仅依据提供者 finality 冻结，不用静默、标点或相同前缀冒充稳定。
- 豆包模式的整段冻结和明确确认流程；未验证停止时不发送，手动停止确认走与正常停止相同的状态同步路径。
- SQLite WAL/FULL 持久化去重与回执：`received` / `applied` / `not_applied` / `unknown`。注入前记账；启动时把未完成的 received 恢复为 unknown；结果未知不自动重试。
- UniFFI Swift 绑定入口及自动化单元、集成和静态检查。

这里的 Apple / 豆包条目指**核心流程与协议实现**，并不表示本仓库已经含有可采集麦克风的原生适配器。

## 构建与测试核心

安装 Rust 工具链后，在仓库根目录执行：

```sh
cargo test --workspace --all-targets
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release -p voice-keyboard-core
```

复现上面已验证的依赖解析时，使用对应 CI 运行中的 `dependency-lockfile` 产物里的 `Cargo.lock`，再执行 `cargo test --locked --workspace --all-targets`。本次原生补充包也包含该实际 CI 锁文件；不要把重新解析依赖的结果当作同一测试环境。

核心输出 `libvoice_keyboard_core` 的 Rust / 静态 / 动态库；**单独运行核心不会录音，也不会向其他应用输入文字**。macOS Native Shell 通过 UniFFI 的 `Core` 接口提交本地命令并处理事件。

## 安全边界

1. 配对不授予远程麦克风权限，必须在语音源端另行授权。
2. `received` 只证明接收，不证明写入。只有平台端给出可核验的写入回执才标为 `applied`。
3. 可能已经产生副作用时，不能切换后端或自动重试；`unknown` 要人工核对。
4. 取消不回删已经输入的内容；丢失焦点不向新输入框发送尾部。
5. 口述正文仅在内存，磁盘保存带密钥摘要、回执和会话墓碑。进程崩溃后的正文恢复不是本实现提供的能力。
6. 本实现使用 Noise 安全通道，**不是 TLS 实现**。尚未进行独立安全审计。
